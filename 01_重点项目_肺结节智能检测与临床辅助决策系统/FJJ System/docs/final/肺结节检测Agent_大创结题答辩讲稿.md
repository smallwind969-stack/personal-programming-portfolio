# 肺结节检测 Agent 大创结题答辩讲稿

对应 PPT：`docs/final/肺结节检测Agent_大创结题答辩PPT.pptx`

建议时长：8-10 分钟

## 1. 开场

各位老师好，我汇报的项目是“肺结节检测/标注与随访 Agent 系统”。这个项目最初是一个肺结节检测与标注演示系统，但在结题冲刺阶段，我们把它升级成了一个更完整的科研闭环：不仅能够做本地 CT 病例的检测、医生复核和随访建议生成，还接入了 LUNA16 公开数据，完成候选池评分、FROC/CPM 评估、后处理分区验证和置信区间分析。

我先说明一个边界：本项目当前公共验证结果来自 LUNA16 subset0 内的分区验证，不是完整 LUNA16 888 个 CT 的官方 leaderboard 成绩。因此我今天会重点汇报系统闭环、可复现实验能力和下一步冲刺路线，而不会夸大临床性能。

## 2. 项目定位

肺结节检测任务的难点不只是“能不能找到结节”，还包括在低假阳性条件下能不能保持检出、医生能不能方便复核、系统能不能给出结构化随访建议，以及实验结果能不能被复现。

所以我们把项目目标拆成两条线：第一条是工程线，完成 CT 导入、候选检测、标注复核和 Agent 随访建议；第二条是科研线，使用公开数据集建立可复现评估流程，用 FROC/CPM 和置信区间报告模型表现。

## 3. 系统闭环

系统工作流包括六个环节：CT/DICOM 导入，候选检测，FPRED 假阳性抑制，医生复核，随访 Agent 建议，以及科研评估材料生成。

这里的核心升级不是单独增加一个模型，而是把检测、人工复核、随访建议、评估脚本和结题材料连起来。这样项目不只是一个能跑的界面，而是一个能持续改进、能留痕、能被审计的科研系统。

## 4. 本地病例证据

本地病例部分目前纳入了 3 个病例，共 607 张 DICOM 切片。我们使用医生复核代理参考来检查系统链路：共有 11 个 reference nodules，其中 7 个来自模型预测，4 个由医生补充。

这里的 proxy precision 是 1.0000，proxy recall 是 0.6364。这个结果只用于工程闭环调试，不能当作正式临床敏感性或特异性。它的意义是证明系统能够完成从检测到复核再到结果导出的全流程。

## 5. Agent 升级

随访 Agent 的价值在于结构化补全和安全边界。它会检查结节大小、密度、数量、风险因素和既往影像等随访相关字段；如果信息缺失，会明确提示，而不是强行给出确定性结论。

当前工作区中保留了 Agent 安全审计记录，3 个病例没有 failed 项。我们把这个 Agent 定位为医生辅助和科研材料自动化工具，不替代临床诊断。

## 6. 公开数据验证

为了避免只停留在本地演示，我们接入了 LUNA16 公开数据。LUNA16 官方数据集共包含 888 个 CT，本项目当前完成的是 subset0：89 个 CT series，112 个官方 annotations，并对完整 candidates_V2 候选池导出了 79,135 条 FPRED 预测。

这个部分是项目科研化的关键，因为它让结果可以按照公开 benchmark 的方式进行 FROC/CPM 评估。

## 7. FPRED 候选分类

在候选分类层面，ResNet-CBAM FPRED 分支在独立候选测试上取得 AUC 0.9926，series-level bootstrap 95% CI 为 0.9731 到 1.0000。在 threshold 0.30 下，sensitivity 为 0.8571，specificity 为 0.9792。

不过这里也要强调：这个 AUC 是候选分类指标，不等同于完整检测系统的端到端 FROC 成绩。因此我们进一步把预测回贴到 LUNA16 世界坐标，做检测层面的 FROC 评估。

## 8. FROC 桥接

完整 candidates_V2 候选池的 raw bridge CPM 是 0.6020。其中 0.125 FP/scan sensitivity 是 0.2143，0.25 FP/scan sensitivity 是 0.2589；在 2 到 8 FP/scan 区间 sensitivity 可以达到 0.8393 到 0.9375。

这说明当前系统在较高假阳性容忍度下能检出较多结节，但低 FP/scan 区间仍然是主要短板。因此下一步需要后处理和 hard-negative mining。

## 9. NMS 分区验证

为了降低调参乐观偏倚，我们没有直接在同一数据上选择和报告 NMS 半径，而是把 subset0 按 annotation 数平衡划分为 calibration 和 evaluation 两部分。calibration 有 55 个 series、56 个 annotations；evaluation 有 34 个 series、56 个 annotations。

NMS 半径只在 calibration 上选择，最终选出 10 mm，然后固定到 evaluation 上报告结果。

## 10. 关键结果

在 evaluation split 上，无 NMS 的 CPM 是 0.6199；固定 10 mm NMS 后，CPM 提升到 0.6888。低假阳性区间也有改善：0.25 FP/scan sensitivity 从 0.3214 提升到 0.4821。

这里需要特别注意，evaluation 上事后扫描时 20 mm 或 30 mm 半径可能更高，但这不能作为最终选择，因为那会把 evaluation 用来调参。我们只报告 calibration 预先选定的 10 mm，这是更严谨的科研口径。

## 11. 置信区间

为了避免只报告单次点估计，我们又做了 series-level bootstrap。固定 10 mm NMS 在 evaluation split 上的 CPM 为 0.6888，95% CI 为 0.6026 到 0.7804；0.25 FP/scan sensitivity 为 0.4821，95% CI 为 0.2833 到 0.6545。

我们以 CT series 为重采样单位，而不是把候选点当作独立样本，因为同一 CT 内候选点之间存在相关性。这一点也更符合 CLAIM 2024 和 TRIPOD+AI 对医学 AI 透明报告的要求。

## 12. 创新与贡献

本项目的创新点可以概括为四个方面。

第一是闭环系统：把检测、标注、医生复核、随访建议和实验导出贯通起来。

第二是科研评估：实现 LUNA16-style FROC/CPM、分区验证和 bootstrap CI，而不是只给分类准确率。

第三是工程能力：实现 candidates_V2 流式评分、断点续跑、NMS sweep 和实验索引。

第四是安全边界：Agent 输出保留缺失字段提示和审计记录，避免过度确定。

## 13. 局限与下一步

当前最大的局限有三点。

第一，公共验证还只覆盖 LUNA16 subset0，不是完整 888 CT 官方成绩。

第二，当前主要是 candidates_V2 加 FPRED 的 bridge 评估，还不是完整端到端 detection submission。

第三，低 FP/scan 区间仍然是短板，且置信区间较宽。

下一步实验路线是：下载并验证 subset1，固定 10 mm NMS 做外部验证；收集高分假阳性做 hard-negative mining；再进行概率校准和消融实验。

## 14. 收尾

总结来说，这个项目已经不只是一个肺结节检测演示系统，而是形成了“系统实现 + 医生复核 + Agent 辅助 + 公开数据评估 + 统计不确定性报告 + 结题材料生成”的闭环。

我们当前不会夸大为完整 LUNA16 世界前沿成绩，但已经具备继续向前沿水平推进的工程和科研基础。结题阶段可以重点展示这个闭环、公开数据实验和严谨的改进路线。

## 15. 可能被问到的问题与回答

### 问题 1：为什么不用 evaluation 上更高的 20 mm NMS？

回答：因为 20 mm 是查看 evaluation sweep 后得到的事后选择。为了避免调参乐观偏倚，我们只报告 calibration split 预先选出的 10 mm 半径。20 mm 可以作为下一轮实验假设，但不能写成当前最终结论。

### 问题 2：AUC 0.9926 和 CPM 0.6888 为什么差别这么大？

回答：AUC 0.9926 是候选分类任务上的结果，输入已经是候选 patch；CPM 0.6888 是检测任务层面的 FROC 指标，需要在 CT 级候选池中同时考虑定位、概率排序和假阳性数量，因此更严格。

### 问题 3：这个系统能不能直接临床使用？

回答：当前定位是科研训练和医生辅助原型，还不能直接作为临床诊断工具。我们已经加入了缺失字段提示和安全审计，但临床使用还需要更大规模、多中心、前瞻性验证和合规审批。

### 问题 4：项目最大的进步是什么？

回答：最大的进步是从“能跑的系统”升级为“能复现实验、能解释结果、能持续迭代的科研闭环”。这比单独追求一个漂亮跑分更适合大创结题和后续论文推进。
