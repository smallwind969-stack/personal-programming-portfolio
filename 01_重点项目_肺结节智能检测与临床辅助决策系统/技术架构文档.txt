================================================================================
三、模块划分与职责
================================================================================

【FJJ System 模块结构】

  app2.py (Web服务层)
    职责：
      - 提供RESTful API接口
      - 处理HTTP请求响应
      - 文件上传下载管理
      - 性能时间记录
    接口：
      - POST /upload       上传DICOM
      - GET  /detect       执行检测
      - POST /identify     执行识别
      - GET  /get_patients 获取病例列表

  engine.py (业务逻辑层)
    职责：
      - 封装完整诊断流程
      - 协调各模型推理
      - 数据预处理
      - 坐标系统转换
    方法：
      - load_itk()              加载医学影像
      - get_vol_1mm()           重采样
      - run_inference()         结节检测
      - identify_malignancy()   良恶性判别

  models.py (模型定义层)
    职责：
      - 定义深度学习模型架构
      - 网络结构搭建
    模型：
      - AttentionVNet_v6_7      VNet分割网络
      - ResNet18_3D_CBAM        ResNet分类网络
      - DualBranchResNet        双分支网络

  monitor_run.py (监控层)
    职责：
      - 监控系统资源占用
      - 生成性能报告
      - 可视化资源曲线

  templates/index.html (前端展示层)
    职责：
      - 用户交互界面
      - 图像可视化展示
      - 标注结果显示
      - 异步请求处理

【标注工具模块结构】

  dicom.annotator5.2(1).py
    组件：
      - InteractiveLabel    交互式图像标注组件
      - MainWindow          主窗口界面
    职责：
      - DICOM序列加载
      - 结节矩形标注
      - 标注数据管理
      - CSV导出

五、技术选型理由
================================================================================

【为什么选择Flask？】
  ✓ 轻量级，适合中小型项目
  ✓ 灵活性高，易于扩展
  ✓ RESTful API设计简单
  ✓ Python生态完善

【为什么选择PyTorch？】
  ✓ 动态图，调试方便
  ✓ 医学影像领域主流框架
  ✓ 社区活跃，预训练模型丰富
  ✓ CUDA加速支持好

【为什么选择SimpleITK？】
  ✓ 医学影像处理标准库
  ✓ 统一DICOM/MHD/NIfTI接口
  ✓ 自动处理序列文件排序
  ✓ 空间信息(间距、原点、方向)完整保留

【为什么选择PyQt6？】
  ✓ 跨平台GUI框架
  ✓ 功能强大，组件丰富
  ✓ 事件驱动模型适合交互应用
  ✓ 与Python集成良好

【为什么选择Canvas而非SVG？】
  ✓ 性能更好，适合实时绘制
  ✓ 像素级控制精确
  ✓ 适合医学影像标注场景
  ✓ 无需DOM操作开销

================================================================================
六、架构特点
================================================================================

【特点一：前后端分离】
  - 前端：纯HTML+JS，无框架依赖
  - 后端：Flask RESTful API
  - 优势：独立开发、独立部署、易于维护

【特点二：模块化设计】
  - 数据处理、模型推理、业务逻辑分离
  - 各模块职责清晰
  - 优势：易于测试、易于扩展

【特点三：级联检测架构】
  - VNet → ResNet → DualBranch
  - 各阶段独立优化
  - 优势：召回率和精确率兼顾

【特点四：异步处理】
  - 前端异步请求(Async/Await)
  - 后端同步处理(可扩展为异步)
  - 优势：用户体验好，不阻塞界面

【特点五：数据预处理与推理分离】
  - 上传时生成预览PNG
  - 推理时使用原始数据
  - 优势：前端加载快，推理精度高
