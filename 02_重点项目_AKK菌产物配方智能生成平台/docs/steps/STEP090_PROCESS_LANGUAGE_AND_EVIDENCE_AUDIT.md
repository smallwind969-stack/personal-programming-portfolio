# STEP090：流程语言与证据展示审计

## 目标

在不主动暴露内部实现术语的前提下，让研发人员能看懂每个环节正在做什么、依据什么、下一步由谁确认，以及何时允许进入下一阶段。

## 本步完成内容

- 数据分析入口使用“研发流程引导”，明确当前任务、前置证据、可执行动作和下一步。
- 数据分析面板使用“六步闭环”呈现阶段状态、进度百分比、证据数量、阻断原因和操作入口。
- 人工确认检查点改为“保留研发人员的最终判断”，避免把内部执行实现直接暴露为产品标题。
- 保留示例数据的隔离、人工推进和不可用于设备控制提示。

## 验证证据

- `npm run build`：通过，所有实验归档、数据分析、仿真模拟、工艺优化路由均完成 TypeScript 与 Next.js 构建。
- `py -m pytest -q`：`339 passed, 1 skipped`。
- `scripts/check-local.ps1`：API 健康检查通过，模型资产 5 个，工作台 `/model-assets` 返回 200。
- 前端可见业务文案扫描：已移除分析流程页面中直接展示的“智能体”表述；内部代码标识保留，不影响运行能力注册和审计链路。

## 仍然保留的边界

- 进度和建议必须以数据、模型指标、证据引用和人工确认作为准入依据。
- 示例演示不等同于企业正式模型，不得用于真实设备控制。
- 本步只收敛展示语言与证据可见性，不改变数据清洗、建模、仿真和优化的计算逻辑。
