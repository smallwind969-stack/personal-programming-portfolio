# Step032：产品创新智能体

日期：2026-07-20

## 目标

把用户本土化自然语言产品构想转化成结构化、可验证、可追溯的产品需求画像，为后续配方研发和工艺优化提供上游目标，但不直接生成最终配方或生产参数。

## 已实现

- 新增供应商无关的 `ProductInnovationProvider` 协议。
- 支持 Ollama 与 OpenAI-compatible 本地模型，使用严格 JSON Schema、有界提示和低温度输出。
- 输入包括产品构想、行业、市场、用户、语言和补充约束，产品构想最大 5000 字符。
- 输出包括工作名称、类别、问题陈述、用户标签、场景、价值主张、目标性能、原材料功能角色、成本假设、工艺/法规约束、风险、未决问题和概念验证计划。
- 原材料只描述功能角色，不含比例；模型返回额外 `ingredientRatio` 字段时整份响应拒绝。
- 证据引用只能来自用户输入、固定研发边界或系统检索到的知识条目。
- 禁止治疗/预防疾病、直接上市保证、最终配方、原料比例、模型晋升、产线控制和代码执行声明。
- 固定研发、安全、法规和设备控制边界由确定性策略补入，模型不能删除。
- 本地模型禁用、超时、不可达、非法 JSON 或策略拒绝时使用确定性产品画像回退。
- 同一命令幂等，不同实验可以并行执行；运行结果按实验隔离、不可变读取。
- 新增 API：
  - `POST /experiments/{experimentId}/product-innovation-runs`
  - `GET /experiments/{experimentId}/product-innovation-runs/{runId}`
- 实验工作区新增“产品创新”入口与 `/experiments/{experimentId}/innovation` 页面。
- 中文工作台支持构想、行业、市场、用户和约束输入，并展示结构化需求画像和人工复核边界。
- 新增 `PRODUCT_INNOVATION_LLM_ENABLED=false` 显式安全开关。

## 边界

- 输出仅为研发实验建议。
- 不产生原料比例、最终配方、模型版本或生产控制参数。
- 当前画像为只读候选，尚未建立“人工确认后传入工艺优化”的权威版本事务。
