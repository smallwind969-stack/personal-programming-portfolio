# STEP046 实施记录：企业设备适配包决策与绑定审计链

日期：2026-07-20

## 已实现

1. 建议请求支持显式选择 `enterpriseKey`、`deviceType` 和 `packVersion`。
2. Agent Worker 通过统一任务载荷接收适配包选择，不依赖 API 进程内存。
3. 适配包在每次读取时重新执行规范 JSON SHA-256 完整性校验。
4. 建议智能体首先按标准字段匹配适配包，其次按设备字段别名匹配。
5. 候选优先级确定为：设备适配包、确定性规则、可选本地大模型。
6. 适配包与规则冲突时保留企业适配候选，同时标记 `adapterRuleConflict` 并要求人工复核。
7. LLM 不能覆盖适配包候选；发生冲突时只增加审计证据。
8. 建议运行保存请求指纹和只读适配包引用。
9. 同一 `commandId` 更换适配包会返回冲突，不会复用旧运行。
10. 正式绑定新增 `suggestionRunId` 和可选 `adapterPack` 来源。
11. 绑定确认 API 会重新核对建议运行、模型版本、适配包三元组、ID 和内容哈希。
12. 组合推理输入返回建议运行和适配包来源，形成从企业设备规则到模型输入的完整审计链。
13. 旧绑定版本仍可在没有适配包来源的情况下读取和运行。
14. 仿真页面新增适配包选择器，并显示企业、设备、版本、条目数和哈希摘要。
15. 建议生成后锁定适配包来源；人工确认阶段不能静默替换。

## 安全边界

- 适配包只描述数据字段和仿真参数映射，不包含设备启动、停止或写寄存器命令。
- 适配包、规则和 LLM 都不能绕过人工确认生成正式绑定。
- 找不到指定适配包时不自动选择“最新版本”或其他企业版本。
- 哈希不一致、建议运行不匹配或模型版本不匹配时拒绝确认。
- 正式绑定仍只服务于研发仿真，不是现实产线控制授权。
