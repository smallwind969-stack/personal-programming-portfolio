# Step 085：跨进程特征门禁与示例仿真准入

## 修复问题

API 进程完成特征集人工确认后，已启动的独立 Worker 仍使用旧内存快照，训练任务错误报告“特征工程需要人工确认”。此外，重复启动脚本会留下多个旧 Worker，它们可能使用旧环境路径抢占新任务。

## 实现

- 特征工程读取前从 SQLite 权威账本刷新当前实验记录。
- 本地启动前终止旧 `app.worker` 进程，只保留一个使用当前配置的 Worker。
- 研究任务、模型注册表和任务队列统一使用 API 运行目录。
- 原始实验数据和对象存储继续使用项目级 `data/runtime`，避免历史实验资产迁移丢失。
- 本地与局域网启动均明确设置 `RESEARCH_RUNNER=sklearn`。
- 隔离示例准入允许选择任意“已保留且具有可审计模型卡”的训练轮次；正式模型晋升仍要求最佳轮次并写入正式注册表。

## 运行态验证

- Worker 成功读取 API 进程确认的特征集，训练轮次不再因跨进程状态陈旧而失败。
- 示例实验 `exp-eebc4a9daa21` 已生成隔离准入记录 `demo-admission-de169fada3da`。
- 数据分析阶段已完成，仿真阶段 `canEnter=true`，工艺优化仍保持锁定。
- 仿真页面返回 200。

## 安全边界

该调整只放宽隔离示例模型的演示选择，不改变企业正式模型晋升、真实测量登记或设备控制门禁。
