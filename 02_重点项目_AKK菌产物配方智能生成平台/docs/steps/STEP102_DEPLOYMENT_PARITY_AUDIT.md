# STEP102 部署一致性审计

## 目标

保证本机、局域网与服务器部署使用同一套流程运行方式、数据目录和健康检查，避免更换启动方式后出现任务不执行、记录丢失或模型配置不一致。

## 本步完成

- 局域网模式补齐后台流程执行器，能够持续推进数据分析、仿真和工艺优化任务。
- 局域网模式统一命令队列、运行记录、产品研判、研究任务、模型资产和实验数据路径。
- 启动局域网模式前停止残留执行器，防止旧环境抢占新任务。
- Docker 前台服务与后台执行器统一运行后端和模型接入参数。
- 后台执行器补齐模型密钥、超时及仿真模型配置透传。
- 服务器部署增加 API `/health`、Web 容器入口和 Nginx 公共入口三层检查。
- 服务器环境模板补充统一运行模式与真实建模执行器配置。

## 闭环说明

同一实验从页面提交后，命令进入持久化队列，由共享数据卷中的后台执行器处理；运行状态、模型版本、仿真结果和优化版本继续写回同一数据目录，再由页面读取并展示。无论使用本机、局域网或服务器入口，过程记录和结果谱系保持一致。

## 验证

- PowerShell 启动与检查脚本语法通过。
- `docker compose config --quiet` 通过。
- Windows 当前未安装可执行的 Bash 环境，服务器脚本的 `bash -n` 留待 Ubuntu 服务器上传后执行。
