# Step033 产品需求确认与版本链

## 本步结果

产品创新智能体的候选结果不再直接流入工艺优化。平台现在形成：

`创新候选 → 人工确认 → 只读需求版本 → 工艺优化冻结引用`

## 已实现

- 人工确认接口，记录确认人、确认理由和命令编号。
- 每个确认版本保存完整需求快照、SHA-256 内容哈希、来源运行和父版本。
- 同一确认命令幂等；同一创新运行禁止重复生成版本；跨实验确认返回 404。
- 支持需求版本列表与最新版本查询。
- 新建工艺优化运行时自动冻结引用当时最新的已确认需求版本。
- 后续确认新需求版本不会改变既有优化运行的来源记录。
- 没有确认需求的历史实验仍可沿用原有 mock 演示，并明确标记为“未引用已确认产品需求”。
- 产品创新页新增“确认并固化版本”操作和版本哈希展示。
- 工艺优化页新增产品需求来源版本展示。

## API

- `POST /experiments/{experimentId}/product-innovation-runs/{runId}/confirm`
- `GET /experiments/{experimentId}/product-requirement-versions`
- `GET /experiments/{experimentId}/product-requirement-versions/latest`

## 当前边界

- 版本仓库仍是第一版内存实现，服务重启后不持久化。
- 工艺优化仍为确定性 mock 演示，不代表真实产线参数。
- 所有固化需求和优化输出均为“研发实验建议”。
- 不生成最终食品配方，不连接真实设备，不下发控制指令。
