# STEP066 隔离演示模型通道

## 解决的问题

示例实验被正确禁止正式模型晋升，但原有仿真只接受正式晋升模型，导致首次体验无法从数据分析进入仿真和工艺优化。本步骤新增独立演示准入，不降低企业正式流程的门禁。

## 已实现

- 新增 `DemoModelAdmission` 及持久化服务。
- 新增接口：
  - `GET /experiments/{experiment_id}/demo-model-admission`
  - `POST /experiments/{experiment_id}/demo-model-admission`
- 演示准入必须满足：
  - 实验来源为 `sample`；
  - 引用当前建模实验最佳保留轮次；
  - 训练轮次具有可审计模型卡；
  - 数据集和模型产物指纹完整；
  - 模型产物通过 SHA-256 完整性校验；
  - 由人工明确提交准入原因。
- 演示模型永远不写入企业正式模型注册表。
- 示例仿真不读取正式模型注册表，也不要求设备特征绑定。
- 示例仿真结果仍使用确定性规则代理，训练模型仅用于血缘和界面演示，页面已明确说明。
- 演示准入评分公开分解为：归一化误差、R²、数据充分性和产物完整性；不是正式模型可靠性结论。
- 示例仿真完成后，只能进入 `rule_demo` 工艺优化，不能冒充正式模型约束优化。
- 原有三条红线保持：不能正式模型晋升、不能登记真实测量、不能发送设备控制指令。
