# STEP091：运行状态业务语言审计

## 目标

让归档、数据分析、仿真和工艺优化页面接收到的运行状态也保持业务语言，不因 API 的状态详情把内部编排实现直接暴露给研发用户。

## 完成内容

- `experiment_service` 的阶段详情由“数据分析智能体可运行”调整为“数据分析流程可运行”。
- 实验模型类型由“待数据分析智能体选择”调整为“待数据分析流程选择”。
- 执行编排事件由“多智能体运行已开始”调整为“流程运行已开始”。
- 演示免责声明统一使用“研发流程演示”，保留确定性演示、证据约束和不可用于生产控制的边界。
- 内部 agent 注册标识、队列、worker 和多核编排代码保持不变，便于后续继续扩展能力。

## 验证

- 前端 `npm run build` 通过。
- 相关后端回归：`8 passed`（实验生命周期、运行时、执行注册表）。
- 上一步完整后端回归仍为 `339 passed, 1 skipped`。
- 本地启动检查已验证 API 健康、模型资产和工作台 HTTP 200。

研发人员看到的是：流程开始、节点完成、证据确认、模型准入、仿真验证和工艺版本更新；系统内部仍由多核能力协同执行，但产品标题和阶段状态不主动强调实现术语。
