# Step034 统一多智能体任务中心

## 本步结果

项目新增跨业务智能体的统一控制平面。产品创新、数据分析、仿真模拟和工艺优化不再只能从各自页面孤立查看，而是被投影为同一张可追溯任务图。

## 架构落实

- 继续复用 Step029 已接入的 LangGraph 状态图适配架构，不再重复创建另一套流程引擎。
- 任务中心定位为只读控制平面，不替代领域编排器。
- 明确三层职责：
  - 业务智能体：产品创新、数据分析、仿真、优化。
  - 工作流智能体：领域内部状态图和人工检查点。
  - 底层工具：文件解析、字段识别、数学计算、本地模型调用。
- `DataCollectionLocalizationAgent` 继续作为数据分析首个业务工作流节点；文件解析器保持底层工具身份。

## 已实现

- 新增统一任务契约：状态、进度、版本、运行编号、依赖、阻塞原因、来源引用、引导/重试能力和页面入口。
- 新增无副作用查询接口，打开任务中心不会静默创建数据分析、仿真或优化运行。
- 产品创新任务区分“候选待确认”和“需求版本已固化”。
- 数据分析任务引用真实运行时编号和业务运行编号。
- 仿真与优化任务展示前置依赖和明确阻塞原因。
- 新增 API：`GET /experiments/{experimentId}/agent-task-center`。
- 新增页面：`/experiments/{experimentId}/agents`。
- 实验工作区新增“智能体任务”中文入口。
- 页面明确不展示或伪造大模型隐藏思维链，只展示可验证算法、指标、输入输出和事件。

## 当前边界

- 当前任务中心是内存运行态的只读聚合；服务重启后运行记录仍会清空。
- 任务中心尚未提供跨实验队列、资源调度、任务优先级和后台 worker。
- 领域智能体仍以确定性 mock 为主，本地 LLM 仅在显式配置时参与。
- 所有输出均为研发实验建议，不连接真实设备。

## 下一步

Step035 将引入持久化检查点与后台任务执行边界：优先采用 LangGraph 官方 checkpoint/store 接口和可替换任务队列适配器，使智能体运行在服务重启后可恢复，并为并发企业实验建立资源隔离基础。
