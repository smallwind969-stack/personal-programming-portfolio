# ROADMAP

## Phase 1: UI + API Mock 闭环

目标：完成可运行的内部研发演示系统。

- Dashboard、AKK 产物库、产物详情、配方生成、配方结果。
- 使用 mock JSON 和规则模板。
- 所有配方输出标记为研发实验建议。
- 展示置信度、风险提示和需要验证的实验指标。

## Phase 2: 产品级 UI 与商品方案工作台

目标：面向下游食品品牌，形成可演示的商品方案共创工作台。

- 商品设计台支持自定义目标商品。
- AKK 原料比例可调整，并实时展示方案预览。
- 方案归档、知识库、实验平台形成完整演示闭环。
- 仍不输出可直接上市的最终食品配方。

## Phase 3: 文献知识库 + RAG 增强

目标：使用本地收集论文搭建可检索、可引用、可解释的知识层。

- 从本地论文资料目录抽取文件名、目录语义和可读取正文片段。
- 生成 `KnowledgeItem` 证据卡片和 `KnowledgeChunk` 检索片段。
- 建立本地轻量向量索引，结合关键词、领域概念、食品基质、证据等级和年份进行混合检索。
- 配方生成时引用相关论文片段，说明引用原因、配比理由、风险边界和验证指标。
- Ollama 可用时使用本地 LLM 做 RAG 增强；不可用时使用规则模板兜底。

## Phase 4: 真实数据库与共创方案库

目标：把 mock JSON 和本地 SQLite 升级为可管理的研发数据库。

- AKK 原料、客户需求、方案结果、实验记录结构化入库。
- 支持方案审核、通过、归档、二次升级。
- 建立共创数据库，沉淀下游客户方案资产。

## Phase 5: 真实配方引擎与预测模型

目标：从演示规则升级为可调参的配方计算和预测服务。

- 引入约束求解、比例优化、成本估算和稳定性评分。
- 接入真实实验数据训练或校准预测模型。
- 每个模型输出保留版本、输入快照、置信度和验证要求。

## Phase 6: 协作、权限与商业化演示

目标：支持多成员、多客户、多项目协作。

- 登录、权限、项目空间、审核流。
- 报告导出、客户版本管理、知识库持续更新。
- 根据目标市场增加法规校验和宣称边界提示。
